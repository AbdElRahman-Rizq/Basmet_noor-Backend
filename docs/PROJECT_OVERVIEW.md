# بصمة نور — نظرة عامة على المشروع

> هذه الوثيقة هي الملخص المرجعي للنطاق (Scope). أي سلوك في النظام يجب أن يكون له أصل في:
> `Basma_Noor_SRS.docx` أو `ERD.txt` أو قرارات العميل المؤكدة في `docs/DECISIONS.md`.
> ما ليس له أصل واضح يوضع في `docs/PENDING_REQUIREMENTS.md` ولا يُنفَّذ.
>
> **قاعدة الاعتماد:** لا مشروع Laravel ولا migrations ولا كود تطبيقي قبل اعتماد الوثائق
> (`FINAL_REVIEW_SUMMARY.md` + `DATABASE_DESIGN.md`). ترتيب التنفيذ:
> **اعتماد الوثائق → تجهيز البيئة → الـ migrations → الـ Backend** (D-039).

---

## 1. الهدف

بناء Backend (REST API) لنظام إدارة مركز/عيادات "بصمة نور" المتخصص في
التنمية التعليمية والعلاجية للأطفال.

النظام يغطي دورة العمل التشغيلية:

```
تسجيل الطفل (كود مجهول الهوية + الإقرارات الثلاثة)
   → إنشاء Case لكل فرع/تخصص (قد يُنشأ قبل إسناد الأخصائي)
   → التقييم المبدئي (مرة واحدة لكل طفل)
   → الخطة العلاجية والأهداف
   → التقرير: رفع PDF + تحديث تقدم الأهداف
   → الواجبات المنزلية
   → متابعة ولي الأمر
```

النظام يدعم **فرعين مبدئيًا** وقابل للتوسع بفرع جديدة بدون تعديل كود.

## 2. المبادئ الحاكمة

| المبدأ | التطبيق |
|---|---|
| خصوصية الطفل | لا يُخزَّن اسم الطفل الحقيقي في أي جدول أو log أو audit trail. المُعرِّف الوحيد هو `child_code`. |
| التحقق من الهوية | Boolean يُسجّله موظف الاستقبال بعد الاطلاع على الهوية يدويًا (لا رفع مستندات). |
| فصل الصلاحيات | SUPER_ADMIN / CO_ADMIN / SPECIALIST / PARENT / RECEPTION، وصلاحيات CO_ADMIN تُضبط لكل حساب على حدة. |
| تتبّع التغييرات | كل عملية حساسة تُسجَّل في `audit_logs` غير القابلة للتعديل أو الحذف. |
| عدم اختراع المتطلبات | أي حقل/حالة/سير عمل غير مؤكد يبقى `null` أو يُؤجَّل، ويُسجَّل في `PENDING_REQUIREMENTS.md`. |
| لا قرار مصادقة ضمني | وجود `email` و`mobile` في `users` لا يعني اعتماد أيهما للدخول؛ Staff (P-32) وParent (P-01) معلّقان. |
| ولي أمر واحد لعدة أطفال | `parents.user_id` unique + `children.parent_id`؛ يُعاد استخدام الحساب ولا يُنشأ مكرر (D-033). |

## 3. الأدوار

| الدور | الوصف | ملاحظات |
|---|---|---|
| `SUPER_ADMIN` | صلاحية كاملة على النظام | يُنشأ بالـ seeder فقط، ولا يُنشئه أي مستخدم آخر. ينشئ حسابات CO_ADMIN. |
| `CO_ADMIN` | إداري بصلاحيات **مخصّصة لكل حساب** يحددها SUPER_ADMIN | ينشئ/يعدّل حسابات SPECIALIST فقط عبر `specialists.manage`؛ لا ينشئ CO_ADMIN/RECEPTION/PARENT، ولا يغيّر الأدوار أو يمنح صلاحيات. |
| `SPECIALIST` | أخصائي | حساب واحد لكل أخصائي، يمكن تعطيله/تفعيله. يرى فقط الـ Cases المسندة إليه. |
| `PARENT` | ولي أمر | حساب واحد يمكن أن يدير عدة أطفال. يرى فقط بيانات أطفاله. **طريقة الدخول/إنشاء الحساب معلّقة P-01/P-29.** |
| `RECEPTION` | استقبال | **الدور والصلاحيات لم يُؤكَّدوا نهائيًا** (SRS يذكر إدخال بيانات، مواعيد، وتحصيل رسوم). البنية RBAC تستوعبه، لكن **بلا أي صلاحية مفعّلة** حتى P-02. |

## 5. خارج النطاق — بشكل صريح

| البند | السبب |
|---|---|
| المحاسبة / الرسوم / المدفوعات / الخصومات | قرار العميل: لا يوجد أي module مالي. |
| جدولة جلسات العلاج | المواعيد للتقييم المبدئي فقط. |
| Entity باسم `sessions` | التقرير نفسه هو سجل الجلسة. |
| مدة خطة ثابتة 6 أشهر | مدة الخطة غير ثابتة. |
| Dynamic Form Builder | أسئلة التقييم تُدار كبيانات (CRUD) لا كمحرك نماذج. |
| قنوات إشعارات (SMS/WhatsApp/Email/Push) | لم تُحدَّد؛ نجهّز الجداول فقط. |
| رفع مرفقات الهوية / صور | التحقق من الهوية Boolean فقط. (ملفات تقارير PDF مستثناة ومطلوبة.) |
| تطبيق موبايل / Frontend | الـ API فقط. |
| سحب الإقرارات (Consent revocation) | **غير محسوم قانونيًا (P-12)** — لا endpoints في v1، ولا يُثبّت كمنع نهائي. |
| تقييم نهائي / تقييم متابعة | SRS يذكر "التقييم النهائي" في بوابة ولي الأمر بدون تعريف → P-21. |
| نص الإقرارات القانوني | ينتظر العميل/القانوني (P-12)؛ لا نص مُختلق في الكود. |
| مصادقة Staff/Parent | تنتظر P-32/P-01؛ لا endpoint قبل القرار. |

## 6. مصادر الحقيقة وترتيب الأولوية

1. **قرارات العميل المؤكدة** في هذا المستند/Prompt (أعلى أولوية).
2. `ERD.txt` المعتمد — بعد تصحيح الملاحظات في `docs/DATABASE_DESIGN.md`.
3. `Basma_Noor_SRS.docx` — للأجزاء غير المتعارضة.

### تعارضات SRS مع القرارات المؤكدة (تم حلها لصالح القرارات)

| SRS | القرار المعتمد |
|---|---|
| حساب استقبال يحصّل الرسوم | لا مالية في النظام. |
| خطة تأهيل 6 شهور | المدة غير ثابتة (`end_date` nullable). |
| "إدارة الجلسات والتقييمات" ككيان جلسات | `reports` هي سجل الجلسة. |
| تسجيل الدخول بكود الطفل + رقم الجوال (ولي الأمر) | يحتاج تأكيد أمني → **P-01**. |
| الأخصائي يدخل بـ Email + Password | تعارض مع نقاش سابق (Mobile + Password) → **P-32**؛ لا اختيار ضمني. |
| إشعار جماعي للإدارة والأخصائيين | القنوات والمستقبلون غير نهائيين → **P-16**. |
| "التقييم النهائي" في بوابة ولي الأمر | غير معرّف → **P-21**. |
| ملاحظات الجلسة الأولى داخل النظام | التقرير PDF فقط حاليًا؛ التعارض محتمل → **P-22**. |
| قسم "شروط ورسوم المركز" | الجزء المالي خارج النطاق. |
| القسم 6 "لوحة تحكم الإدارة" | **فارغ في ملف الـ SRS** — لا يوجد محتوى. |

|---|---|

**النتيجة:** التشغيل سيكون عبر Docker Compose:
`php:8.4-cli` + `postgres:17-alpine`. وتم اختيار **Laravel 13.x** (آخر إصدار مستقر،
يتطلب PHP ^8.3) و**Laravel Sanctum 4.x**.

> **شرطان لبدء التنفيذ:** (1) اعتماد الوثائق (Gate A)، (2) نجاح تجهيز البيئة (Gate B).
> **Gate B بنية تحتية فقط:** لم يُنشأ مشروع Laravel داخله. تم إنشاء Laravel 13 **بعد اعتماد Gate A** (T-0.2).
> لا migrations ولا كود تطبيقي قبل Gate C.

## 9. مصطلحات

| المصطلح | المعنى |
|---|---|
| Child Code | كود مجهول الهوية مكوّن من أول حرفين إنجليزيين من اسم الطفل + أول حرفين إنجليزيين من اسم ولي الأمر + رقم تسلسلي global. الأسماء تُدخل بالإنجليزية (D-041). |
| Case | ملف حالة لطفل داخل فرع معيّن. الأخصائي **nullable حتى الإسناد**؛ الطفل يمكن أن يكون له عدة Cases. |
| Initial Assessment | تقييم مبدئي واحد لكل طفل (وليس لكل Case). |
| Report | ملف PDF مرفوع يمثل سجل الجلسة (لا يوجد كيان Session). الإخفاء عن ولي الأمر لا يخفيه عن الإدارة (D-043). |
| Goal | هدف داخل خطة علاجية، له أخصائي مسؤول واحد ونسبة تقدم وسجل تاريخي. |
| Plan Specialist | أخصائي مشارك/مسؤول في الخطة عبر `plan_specialists`؛ الخطة قد يكون لها أكثر من واحد (D-040). لا يمنح وصولًا تلقائيًا للحالة. |
| Parent Account | حساب واحد لولي الأمر يدير عدة أطفال؛ لا يُكرر عند تسجيل طفل جديد. طريقة الدخول ومفتاح المطابقة معلّقان P-01، ورقم الجوال وحده ليس المفتاح المعتمد (D-044). Find-or-Create محظور حتى تأكيد الهوية. |
| Specialist Comment | تعليق اختياري بجانب درجة المقياس الوظيفي في `functional_scale_scores`، لا يُفرض في validation (D-045). |
| Audit Log | سجل غير قابل للتعديل لعمليات المستخدمين الحساسة. |
