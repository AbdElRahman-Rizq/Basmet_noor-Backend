# بصمة نور — متطلبات معلّقة (تحتاج تأكيد العميل)

> **قاعدة العمل:** أي بند هنا **لا يُنفَّذ** حتى يتم تأكيده. لا نضع افتراضات في الكود.
> **الحالة:** ⛔ يمنع بدء المرحلة | ⚠️ يؤثر على مرحلة قادمة | 💡 تحسين/توضيح
> **آخر تحديث:** 2026-11-12

---

## 1. أسئلة حاجزة (⛔) — مطلوبة قبل Phase 1

### P-01 — طريقة دخول ولي الأمر
- **المصدر:** SRS §1 "الدخول بكود الطفل ورقم الجوال" مقابل قرار العميل بوجود "حساب Parent".
- **السؤال:** هل الدخول بـ (child_code + mobile) فقط بدون password؟ أم mobile/email + password؟
  وهل يمكن لولي الأمر الذي لديه عدة أطفال الدخول بحساب واحد؟
- **المخاطر:** (child_code + mobile) بدون كلمة مرور = مصادقة ضعيفة؛ كود الطفل قد يكون معروفًا
  لموظفين/أقارب، ورقم الجوال قابل للتخمين في نطاق محدود.
- **التوصية:** حساب بكلمة مرور + mobile كـ username، مع إعادة تعيين عبر رسالة SMS (لاحقًا)،
  وربط الحساب بأطفاله تلقائيًا. منع أي مصادقة تعتمد على كود الطفل وحده.
- **الأثر إن لم يُحسم:** لا يمكن بناء `ParentAuthController`، ولا اختبارات "Parent sees only own children".

### P-02 — دور RECEPTION وصلاحياته
- **السؤال:** هل دور الاستقبال موجود فعلًا؟ ما الصلاحيات بالضبط: تسجيل طفل؟ إنشاء Case؟ إسناد أخصائي؟
  تسجيل إقرارات؟ جدولة مواعيد؟ تعديل بيانات؟ وهل يمكنه رؤية التقارير؟
- **ملاحظة:** SRS يذكر "تحصيل الرسوم" وهو خارج النطاق — لذا نستبعد الجزء المالي فقط.
- **التوصية:** تفعيل: create child, create parent/guardian, appointments, record consents, view own branch children.
  بدون: plans, goals, reports content, audit logs.

### P-03 — قواعد توليد كود الطفل
- **السؤال:**
  1. هل الحروف لاتينية (A–Z) مشتقة آليًا من الاسم العربي، أم يُدخلها الموظف يدويًا؟ (المثال `AMRA1` لاتيني).
  2. ما القاعدة للاسم المركّب مثل "عبد الرحمن"؟ أول حرفين من الكلمة الأولى ("AB") أم من الاسم كاملًا ("AA")؟
  3. ماذا لو كان الاسم أقل من حرفين، أو أجنبيًا (غير عربي)؟
  4. هل البادئة "ال" تُحذف؟
- **التوصية:** أول حرفين من الكلمة الأولى بعد التطبيع، transliteration آلي، رفض الاسم < حرفين.

### P-04 — اسم ولي الأمر وتاريخ الميلاد
- **السؤال:** هل يُسمح بتخزين **اسم ولي الأمر** في قاعدة البيانات؟ (المتطلب يمنع اسم الطفل فقط،
  لكن SRS يقول "تسجيل بدون أسماء").
- **سؤال تابع:** هل تُخزَّن `age` فقط كما في ERD، أم `date_of_birth` (أدق ولا يتقادم)؟
- **التوصية:** تخزين اسم ولي الأمر (مطلوب قانونيًا للإقرارات والإثبات)، وعدم تخزين اسم الطفل.
  أما العمر: `age` + `age_recorded_at` كما في التصميم، أو DOB لو وافق العميل.

## 2. أسئلة تؤثر على التصميم (⚠️)

### P-05 — حالات الـ Case
القيم غير نهائية. **لا نُنشئ enum ولا state machine ولا سجل تغييرات.**
السؤال: ما القيم؟ (open / in_progress / closed / transferred / cancelled؟) ومن يغيّرها؟

### P-06 — أنواع الخطة العلاجية
"Integration" و"Individual" — هل هذان الاسمان نهائيان؟ هل توجد أنواع أخرى؟
مطلوب للأعمدة `plan_type` والـ validation.

### P-07 — قالب التقرير النهائي
لم يُسلَّم. نحتاج: الحقول، الإلزامي/الاختياري، هل التقرير editable بعد الحفظ؟ هل يُحذف؟
من يحق له إخفاء التقرير عن ولي الأمر؟ هل الإخفاء دائم أم قابل للإلغاء؟
**التوصية المؤقتة:** أعمدة أساسية + `details jsonb`، والإخفاء بتفويض `reports.hide_from_parent`.

### P-08 — تعديل التقييم المبدئي بعد الحفظ
هل يمكن تعديل الإجابات/الدرجات؟ من؟ وهل يُسجَّل التعديل في audit فقط أم نحتاج تاريخ نسخ؟
**التوصية:** التقييم يُقفل بعد الحفظ (immutable)، والتعديل يحتاج قرارًا صريحًا.

### P-09 — أسماء المقاييس الوظيفية العشرة وطبيعة الدرجة
SRS يذكر أمثلة (الانتباه، اتباع التعليمات، التخاطب، التفاعل الاجتماعي، المعالجة الحسية، السلوك...)
لكن القائمة الكاملة غير موجودة. هل الدرجة integer فقط (0–10) أم تقبل كسورًا؟

### P-10 — محتوى أسئلة التقييم المبدئي
SRS يحيل إلى ملف `استمارة التقييم.pdf` غير المرفق. لا يوجد أي محتوى أسئلة.
**التوصية:** بناء إدارة الأسئلة (CRUD) + شاشة إدخال، وترك المحتوى للإدارة عبر النظام،
أو انتظار الملف لإضافته في Seeder.

### P-11 — المعززات
هل قائمة المعززات ثابتة يديرها الأدمن (catalog)، أم نص حر لكل طفل؟
وهل يوجد "درجة فعالية" أم اختيار فقط؟ **التوصية:** catalog + اختيار + notes.

### P-12 — الإقرارات: مَن يُسجّلها؟
هل يضغط ولي الأمر بنفسه في التطبيق، أم موظف الاستقبال يسجّل إقرارًا ورقيًا؟
وهل نحتاج نص الإقرار ونسخته (version) لحظة الموافقة؟

### P-13 — إنشاء Case بدون أخصائي
هل يستطيع الاستقبال/الأدمن إنشاء Case قبل تعيين أخصائي؟
- لو نعم → `cases.specialist_id` يجب أن يكون **nullable** ونمنع التفعيل حتى الإسناد.
- لو لا → يبقى NOT NULL كما في الـ ERD.
**حاليًا:** التصميم يفرض NOT NULL (تفسير حرفي للمتطلب).

### P-14 — علاقة هدف الخطة بأخصائيي الخطة
هل يجب أن يكون `goals.specialist_id` ضمن `plan_specialists`؟
**التوصية:** نعم (validation تطبيقي، ليس FK مركّب).

### P-15 — المواعيد
- هل الموعد مرتبط بأخصائي معيّن؟
- ما حالات الموعد (scheduled / confirmed / cancelled / completed / no_show)؟
- هل يوجد إلغاء/إعادة جدولة؟ وهل يُسجَّل سبب؟
- هل الموعد لطفل واحد أم يمكن أن يشمل أكثر من طفل؟
**حاليًا:** لا نضيف أي حقل غير موجود في الـ ERD.

### P-16 — الإشعارات
- القنوات المطلوبة (in-app / email / SMS / WhatsApp / push)؟
- مَن يستقبل ماذا؟ (إدارة، أخصائي، ولي أمر)
- هل إشعار "موعد تقييم جديد" جماعي للإدارة والأخصائيين أم لفرد؟
- هل يوجد إشعار للواجبات والتقارير؟
**حاليًا:** جدول + قراءة/تعليم مقروء فقط.

### P-17 — الواجبات المنزلية
- هل يمكن للأخصائي تعديل/حذف واجب بعد إنجازه من ولي الأمر؟
- هل يمكن إعادة فتح الواجب (إلغاء الإنجاز)؟
- هل يمكن لولي الأمر إضافة أكثر من تعليق؟ هل يمكنه تعديل تعليقه؟
- هل "الحالة" هي pending/completed فقط؟
**التوصية:** comments append-only، والإنجاز نهائي إلا بقرار.

### P-18 — سجلات التدقيق
- مَن يرى `audit_logs`؟ (SUPER_ADMIN فقط أم CO_ADMIN أيضًا؟)
- مدة الاحتفاظ؟ (هل يوجد متطلب قانوني للحذف بعد مدة؟)
- هل تُسجَّل عمليات القراءة الحساسة (view) أم عمليات التعديل فقط؟
**التوصية:** التعديل/الإنشاء/الحذف/تسجيل الدخول الفاشل، وقراءة سجلات الأطفال الحساسة.

### P-19 — تعديل بيانات الطفل بعد التسجيل
هل يمكن تعديل `age` أو `nationality` أو `neighborhood`؟ مَن؟ وهل يُسجَّل في audit؟
هل يمكن نقل الطفل لولي أمر آخر (تغيّر الوصاية)؟

### P-20 — الحذف النهائي / حق المحو
هل يوجد متطلب لحذف بيانات طفل نهائيًا (right to erasure)؟ أم الأرشفة فقط؟
**حاليًا:** soft delete فقط، ولا حذف نهائي لأي سجل طبي.

### P-21 — "التقييم النهائي"
SRS §5 يذكر "التقييم النهائي" لولي الأمر. هل هو:
(a) نتائج التقييم المبدئي فقط؟ (b) تقييم منفصل بعد فترة؟ (c) ملخص من الخطة والأهداف؟
**حاليًا:** غير منفَّذ.

### P-22 — ملاحظات الجلسة الأولى
SRS §4 يذكر حقول: مدة الانتباه، المشتتات، السلوكيات، مستوى المساعدة.
هل هذه حقول داخل التقرير الأول أم كيان منفصل؟ **التوصية:** تقرير أول (report) بحقول في `details`.

### P-23 — لغة رسائل الـ API
عربي أم إنجليزي أم كلاهما (Accept-Language)؟ **التوصية:** إنجليزي للمفاتيح + رسائل عربية.

### P-24 — بيانات الفرع
هل نحتاج عنوان/هاتف/ساعات عمل للفرع؟ غير موجود في الـ ERD. **التوصية:** لاحقًا.

### P-25 — "شروط ورسوم المركز"
الجزء المالي خارج النطاق. هل المطلوب عرض نص الشروط/اللوائح فقط (Static content) بدون مبالغ؟
