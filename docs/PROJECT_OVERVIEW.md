# بصمة نور — نظرة عامة على المشروع

> هذه الوثيقة هي الملخص المرجعي للنطاق (Scope). أي سلوك في النظام يجب أن يكون له أصل في:
> `Basma_Noor_SRS.docx` أو `ERD.txt` أو قرارات العميل المؤكدة في `docs/DECISIONS.md`.
> ما ليس له أصل واضح يوضع في `docs/PENDING_REQUIREMENTS.md` ولا يُنفَّذ.

---

## 1. الهدف

بناء Backend (REST API) لنظام إدارة مركز/عيادات "بصمة نور" المتخصص في
التنمية التعليمية والعلاجية للأطفال.

النظام يغطي دورة العمل التشغيلية:

```
تسجيل الطفل (كود مجهول الهوية + الإقرارات الثلاثة)
   → إنشاء Case لكل فرع/تخصص (قد يُنشأ قبل إسناد الأخصائي)
   → التقييم المبدئي (مرة واحدة لكل طفل)
   → الخطة العلاجية والأهداف
   → التقرير: رفع PDF + تحديث تقدم الأهداف
   → الواجبات المنزلية
   → متابعة ولي الأمر
```

النظام يدعم **فرعين مبدئيًا** وقابل للتوسع بفرع جديدة بدون تعديل كود.

## 2. المبادئ الحاكمة

| المبدأ | التطبيق |
|---|---|
| خصوصية الطفل | لا يُخزَّن اسم الطفل الحقيقي في أي جدول أو log أو audit trail. المُعرِّف الوحيد هو `child_code`. |
| التحقق من الهوية | Boolean يُسجّله موظف الاستقبال بعد الاطلاع على الهوية يدويًا (لا رفع مستندات). |
| فصل الصلاحيات | SUPER_ADMIN / CO_ADMIN / SPECIALIST / PARENT / RECEPTION، وصلاحيات CO_ADMIN تُضبط لكل حساب على حدة. |
| تتبّع التغييرات | كل عملية حساسة تُسجَّل في `audit_logs` غير القابلة للتعديل أو الحذف. |
| عدم اختراع المتطلبات | أي حقل/حالة/سير عمل غير مؤكد يبقى `null` أو يُؤجَّل، ويُسجَّل في `PENDING_REQUIREMENTS.md`. |

## 3. الأدوار

| الدور | الوصف | ملاحظات |
|---|---|---|
| `SUPER_ADMIN` | صلاحية كاملة على النظام | يُنشأ بالـ seeder فقط، ولا يُنشئه أي مستخدم آخر. |
| `CO_ADMIN` | إداري بصلاحيات **مخصّصة لكل حساب** يحددها SUPER_ADMIN | يستطيع إنشاء حسابات SPECIALIST فقط، ولا يستطيع إنشاء أي حساب إداري. |
| `SPECIALIST` | أخصائي | حساب واحد لكل أخصائي، يمكن تعطيله/تفعيله. يرى فقط الـ Cases المسندة إليه. |
| `PARENT` | ولي أمر | حساب واحد يمكن أن يدير عدة أطفال. يرى فقط بيانات أطفاله. |
| `RECEPTION` | استقبال | **الدور والصلاحيات لم يُؤكَّدوا نهائيًا** (SRS يذكر إدخال بيانات، مواعيد، وتحصيل رسوم). سنبني البنية RBAC لتستوعبه دون تفعيل صلاحيات غير مؤكدة. |

## 5. خارج النطاق — بشكل صريح

| البند | السبب |
|---|---|
| المحاسبة / الرسوم / المدفوعات / الخصومات | قرار العميل: لا يوجد أي module مالي. |
| جدولة جلسات العلاج | المواعيد للتقييم المبدئي فقط. |
| Entity باسم `sessions` | التقرير نفسه هو سجل الجلسة. |
| مدة خطة ثابتة 6 أشهر | مدة الخطة غير ثابتة. |
| Dynamic Form Builder | أسئلة التقييم تُدار كبيانات (CRUD) لا كمحرك نماذج. |
| قنوات إشعارات (SMS/WhatsApp/Email/Push) | لم تُحدَّد؛ نجهّز الجداول فقط. |
| رفع مرفقات الهوية / صور | التحقق من الهوية Boolean فقط. (ملفات تقارير PDF مستثناة ومطلوبة.) |
| تطبيق موبايل / Frontend | الـ API فقط. |
| سحب الإقرارات (Consent revocation) | غير مسموح حاليًا حسب المتطلبات. |
| تقييم نهائي / تقييم متابعة | SRS يذكر "التقييم النهائي" في بوابة ولي الأمر بدون تعريف → PENDING. |

## 6. مصادر الحقيقة وترتيب الأولوية

1. **قرارات العميل المؤكدة** في هذا المستند/Prompt (أعلى أولوية).
2. `ERD.txt` المعتمد — بعد تصحيح الملاحظات في `docs/DATABASE_DESIGN.md`.
3. `Basma_Noor_SRS.docx` — للأجزاء غير المتعارضة.

### تعارضات SRS مع القرارات المؤكدة (تم حلها لصالح القرارات)

| SRS | القرار المعتمد |
|---|---|
| حساب استقبال يحصّل الرسوم | لا مالية في النظام. |
| خطة تأهيل 6 شهور | المدة غير ثابتة (`end_date` nullable). |
| "إدارة الجلسات والتقييمات" ككيان جلسات | `reports` هي سجل الجلسة. |
| تسجيل الدخول بكود الطفل + رقم الجوال | يحتاج تأكيد أمني (PENDING Q-01). |
| إشعار جماعي للإدارة والأخصائيين | القنوات والمستقبلون غير نهائيين. |
| "التقييم النهائي" في بوابة ولي الأمر | غير معرّف → PENDING Q-21. |
| قسم "شروط ورسوم المركز" | الجزء المالي خارج النطاق. |
| القسم 6 "لوحة تحكم الإدارة" | **فارغ في ملف الـ SRS** — لا يوجد محتوى. |

## 9. مصطلحات

| المصطلح | المعنى |
|---|---|
| Child Code | كود مجهول الهوية مكوّن من حرفين من اسم الطفل + حرفين من اسم ولي الأمر + رقم تسلسلي global. |
| Case | ملف حالة لطفل داخل فرع معيّن، له أخصائي مسؤول. الطفل يمكن أن يكون له عدة Cases. |
| Initial Assessment | تقييم مبدئي واحد لكل طفل (وليس لكل Case). |
| Report | سجل جلسة علاجية (لا يوجد كيان Session). |
| Goal | هدف داخل خطة علاجية، له نسبة تقدم وسجل تاريخي للتقدم. |
| Audit Log | سجل غير قابل للتعديل لعمليات المستخدمين الحساسة. |
